## 用户态与内核态、切换方式（面试高频）

### 4.1.1 用户态 vs 内核态

#### 用户态（User Mode）
- 权限低
- 不能直接访问硬件、不能执行特权指令
- 需要通过 **系统调用** 请求内核服务

#### 内核态（Kernel Mode）
- 权限最高
- 可以访问所有硬件、管理内存、调度进程
- 操作系统核心代码运行在内核态

一句话：

> **用户态受限制，内核态无所不能。**



### 4.1.2 用户态与内核态的切换方式

#### 1）系统调用（最常见）
用户程序 → syscall → 内核态执行 → 返回用户态

流程：
1. 用户程序发起系统调用
2. 执行 `syscall` / `int 0x80`
3. CPU 切换到内核态，保存上下文
4. 内核执行系统调用逻辑
5. 恢复上下文，返回用户态

#### 2）中断（硬件触发）
如定时器中断、网卡中断  
→ CPU 自动进入内核态执行 ISR  
→ ISR 完成后恢复用户态

#### 3）异常（程序错误）
如除零、非法访问  
→ CPU 进入内核态执行异常处理程序  
→ 可能终止进程



### 4.1.3 切换开销（面试必问）

- **上下文切换成本高**（保存/恢复寄存器、栈）
- **CPU 缓存失效**
- **模式切换本身有成本**

一句话：

> **用户态 ↔ 内核态切换很贵，能少则少。**



### 4.1.4 为什么要区分用户态和内核态？

- **安全性**：防止用户程序破坏系统
- **稳定性**：用户程序崩溃不会影响内核
- **资源管理**：统一管理内存、进程、设备

一句话：

> **隔离用户与内核，是为了安全、稳定、可控。**



## 用户空间与内核通信方式（面试常考）

### 4.2.2 常见通信方式

| 方式 | 特点 | 使用场景 |
|------|------|-----------|
| **系统调用** | 最标准、最安全 | 所有用户态访问内核的入口 |
| **字符设备 /dev/** | 文件接口统一 | 驱动开发 |
| **procfs /proc** | 文本接口 | 查询内核状态 |
| **sysfs /sys** | 一文件一属性 | 设备模型、驱动参数 |
| **Netlink** | 双向通信、异步 | 网络子系统、udev |
| **mmap 共享内存** | 零拷贝、高性能 | 大数据传输 |
| **信号** | 异步通知 | 事件触发 |

一句话：

> **系统调用最通用，mmap最快，Netlink最灵活，proc/sysfs最易用。**



## 原码、反码、补码（必考基础）

### 4.3.1 原码
- 最高位符号位
- 存在 +0 / -0
- 运算复杂

### 4.3.2 反码
- 负数：符号位不变，其余位取反
- 仍有 +0 / -0
- 需要循环进位

### 4.3.3 补码（现代计算机统一使用）
- 负数 = 反码 + 1
- 只有一个 0
- 加减统一用加法实现
- 硬件最简单

### 为什么使用补码？
1. 加减法统一
2. 没有双零问题
3. 硬件实现最简单
4. 能表示最小负数（如 -128）

一句话：

> **补码让加减法变成加法，硬件最简单，所以被统一采用。**



## 内存碎片（外部碎片 vs 内部碎片）

### 4.4.1 外部碎片（External Fragmentation）
- 空闲内存不连续
- 总量够但无法分配大块
- 典型于 malloc/free

解决：
- 内存紧凑（Compaction）
- Buddy System
- Slab 分配器
- 内存池



### 4.4.2 内部碎片（Internal Fragmentation）
- 分配的内存 > 实际需要
- 由对齐、最小分配单位导致

解决：
- 内存池
- 更细粒度分配器
- 自定义 allocator



### 4.4.3 特殊碎片
- 文件系统碎片
- 共享内存碎片



### 4.4.4 总结

> **外部碎片：空闲不连续；内部碎片：分配过大。**



## 最终面试总结（可直接背）

- **用户态 vs 内核态**：权限不同，系统调用/中断/异常触发切换  
- **切换开销大**：上下文切换 + 缓存失效  
- **通信方式**：syscall、/dev、proc、sysfs、Netlink、mmap、signal  
- **补码**：统一加减法、硬件简单、无双零  
- **内存碎片**：外部碎片（不连续）、内部碎片（对齐浪费）
