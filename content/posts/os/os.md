# 多线程编程


---

## 多进程内存共享可能存在的问题及处理方法

### 1. 内存一致性问题（Memory Consistency）
多个进程可能缓存共享数据，导致：

- A 进程写入后，B 进程由于缺少同步关系而观察到旧值或不一致状态
- 多核 CPU 上出现乱序执行导致读写顺序不一致

**本质原因：**  
共享内存不会自动建立互斥和 happens-before。主流 cache-coherent 多核通常由硬件维护缓存一致性，但这不能消除数据竞争、编译器/CPU 重排和发布—获取顺序问题，仍需锁或具有正确内存序的原子操作。

---

### 2. 并发访问问题（Race Condition）
多个进程同时读写共享变量时，会出现：

- 数据竞争（Data Race）
- 写覆盖写
- 读到中间状态的数据

例如两个进程同时执行 `counter++`，可能导致最终值错误。

---

### 3. 同步问题（Lack of Synchronization）
共享内存本身不带同步机制，进程之间必须自行协调：

- 谁先读？
- 谁先写？
- 写完是否通知其他进程？

如果没有同步，就会出现混乱。

---

### 4. 死锁问题（Deadlock）
如果多个进程使用锁不当，会出现：

- A 等 B 的锁
- B 等 A 的锁

最终所有进程都卡住。

---

### 5. 内存泄漏与资源未释放
共享内存属于系统资源，如果：

- 创建后未 `shmctl(..., IPC_RMID)`
- POSIX `shm_unlink()` 未调用
- Windows `CloseHandle()` 未调用

就会导致系统资源泄漏。

---

## 处理方法

### 1. 使用 IPC 同步机制（必备）

共享内存必须配合同步机制使用：

- **信号量（Semaphore）**：最常用的进程同步方式  
- **互斥锁（Mutex）**：POSIX 支持 *进程间互斥锁*（需要放在共享内存中）
- **读写锁（RWLock）**：读多写少场景
- **条件变量（Condition Variable）**：用于事件通知

示例（POSIX 信号量）：

```c
sem_t* sem = sem_open("/mysem", O_CREAT, 0666, 1);
sem_wait(sem);   // P 操作
// 临界区
sem_post(sem);   // V 操作
```

---

### 2. 使用原子操作（Atomic Operations）

对于简单操作（如计数器）可以使用：

- GCC 原子内建函数（`__sync_*` / `__atomic_*`）
- C11 原子类型（`stdatomic.h`）
- Linux futex（底层机制）

优点：无需锁，性能高  
缺点：只适用于简单读写，不适合复杂临界区

---

### 3. 使用内存屏障（Memory Barrier）

多核 CPU 上可能出现：

- 写操作被重排
- 缓存未及时刷新

解决方法：

- 使用 `__sync_synchronize()`（GCC）
- C11 `atomic_thread_fence()`
- 内核中的 `smp_mb()`、`mfence` 指令

作用：  
**确保读写顺序正确，避免 CPU 重排序导致的数据不一致。**

---

### 4. 正确管理共享内存生命周期

POSIX：

```c
int id = shmget(...);
void* ptr = shmat(id, NULL, 0);
// 使用结束后
shmdt(ptr);
shmctl(id, IPC_RMID, NULL);  // 删除共享内存
```

POSIX shm_open：

```c
shm_unlink("/myshm");
```

Windows：

```cpp
CloseHandle(hMapFile);
```

避免系统资源泄漏。

## 常用技术和方法

### POSIX 共享内存（System V / POSIX）

#### 创建共享内存：

```c
int shm_id = shmget(IPC_PRIVATE, SHM_SIZE, IPC_CREAT | 0666);
char* shm_ptr = (char*)shmat(shm_id, NULL, 0);
```

#### 配合信号量同步：

```c
sem_t* semaphore = sem_open("/mysem", O_CREAT, 0666, 1);
sem_wait(semaphore);
// 临界区
sem_post(semaphore);
```

---

### Windows 共享内存

#### 创建共享内存：

```cpp
HANDLE hMapFile = CreateFileMapping(INVALID_HANDLE_VALUE, NULL,
    PAGE_READWRITE, 0, SIZE, L"MySharedMemory");

LPCTSTR pBuf = (LPTSTR)MapViewOfFile(hMapFile,
    FILE_MAP_ALL_ACCESS, 0, 0, SIZE);
```

同步机制：

- `CreateMutex()`
- `CreateSemaphore()`

---

### 内存映射文件（Memory-Mapped File）

适用于：

- 大文件共享
- 跨进程共享数据
- 高效 I/O

本质：  
**把文件映射到多个进程的虚拟地址空间，实现共享。**

---

## 最终总结

> **多进程共享内存的问题主要来自“没有同步”。**  
> 典型问题包括：数据不一致、竞态条件、死锁、缓存不一致、资源泄漏。  
> 解决方法是：**共享内存 + 同步机制（信号量/互斥锁/原子操作/内存屏障）+ 正确的生命周期管理。**

## 进程上下文（Process Context）

**进程上下文（Process Context）**指的是：

> **CPU 为了让一个进程能够“被中断后继续执行”，必须保存和恢复的全部运行环境。**

换句话说：

- 上下文 = 进程运行所需的全部状态  
- 上下文切换 = 保存旧进程 → 恢复新进程

---

## 4.18.2 进程上下文包含的内容

进程上下文是一个“大集合”，包含 CPU、内存、内核等多方面信息。

### 1. CPU 寄存器状态（最核心）
- 程序计数器（PC / RIP）  
- 栈指针（SP / RSP）  
- 通用寄存器（AX、BX、CX…）  
- 状态寄存器（PSW / EFLAGS）  

这些寄存器决定了：

> **CPU 下一条指令从哪里执行、栈在哪里、当前计算状态是什么。**

---

### 2. 虚拟内存信息
- 页表基址（CR3）
- 虚拟地址空间布局（代码段、数据段、堆、栈）
- 内存映射（mmap 文件映射等）

进程切换时必须切换页表，因此：

> **进程上下文切换比线程切换更慢。**

---

### 3. 内核相关信息
- 内核栈（每个进程一个）
- PCB（Process Control Block）/ Linux 的 `task_struct`
- 打开的文件描述符表
- 信号处理函数
- 进程凭证（UID、GID）

---

### 4. 调度相关信息
- 进程状态（running、ready、blocked）
- 优先级
- 时间片
- 调度策略（CFS、RR 等）

---

## 4.18.3 进程上下文切换（Context Switch）

### 触发时机

- 时间片耗尽（抢占式调度）
- 进程主动 sleep / yield
- 等待 I/O（阻塞）
- 高优先级进程抢占
- 系统调用 / 中断返回

---

### 切换过程（简化）

1. **保存当前进程上下文**  
   保存寄存器、PC、SP、内核栈等到 PCB

2. **更新当前进程状态**  
   running → ready / blocked

3. **调度器选择下一个进程**

4. **恢复新进程上下文**  
   恢复寄存器、页表、内核栈等

5. **CPU 开始执行新进程**

---

## 4.18.4 进程上下文 vs 线程上下文

| 对比项 | 进程上下文 | 线程上下文 |
|--------|------------|------------|
| 切换内容 | 寄存器 + 页表 + 内核栈 + PCB | 寄存器 + 内核栈 + TCB |
| 是否切换地址空间 | **是**（切换页表） | **否**（共享地址空间） |
| 切换开销 | **大** | **小** |
| 资源隔离 | 强 | 弱 |
| 典型用途 | 独立程序 | 并发执行单元 |

一句话总结：

> **线程切换只换寄存器，进程切换还要换页表，所以进程切换更慢。**

---

## 4.18.5 总结（面试高频版）

- **进程上下文 = CPU 能“接着跑”一个进程所需的全部状态。**
- 包含：寄存器、页表、内核栈、PCB、调度信息等。
- **进程上下文切换开销大**，因为需要切换页表、刷新 TLB。
- **线程上下文切换更轻量**，因为线程共享进程的地址空间。

## 线程之间的同步机制

### 为什么需要线程同步

线程共享同一进程的地址空间，因此：

- 多线程可以同时访问同一块内存
- 如果没有同步，会出现：
  - **数据竞争（Data Race）**
  - **读写不一致**
  - **临界区冲突**
  - **程序崩溃或逻辑错误**

同步机制的本质：

> **控制多个线程访问共享资源的顺序，保证临界区的正确性。**

---

### 常见线程同步机制

#### （1）互斥锁（Mutex）

保证同一时刻只有一个线程进入临界区。

```c
pthread_mutex_t lock;
pthread_mutex_lock(&lock);
// 临界区
pthread_mutex_unlock(&lock);
```

**特点：**

- 使用最广
- 适合保护共享资源
- 可能阻塞线程

---

#### （2）读写锁（Read-Write Lock）

- 多个读者可并发
- 写者独占

```c
pthread_rwlock_rdlock(&rwlock);   // 读锁
pthread_rwlock_wrlock(&rwlock);   // 写锁
pthread_rwlock_unlock(&rwlock);
```

**适用场景：**

- **读多写少** 的场景（如缓存、配置读取）

---

#### （3）条件变量（Condition Variable）

用于线程间事件通知，常与互斥锁配合使用。

```c
pthread_mutex_lock(&lock);
pthread_cond_wait(&cond, &lock);  // 等待事件
pthread_mutex_unlock(&lock);
```

**特点：**

- 避免忙等
- 实现生产者-消费者模型的核心机制

---

#### （4）信号量（Semaphore）

基于计数的同步机制，可用于线程或进程。

```c
sem_wait(&sem);   // P 操作
sem_post(&sem);   // V 操作
```

**特点：**

- 可实现互斥（计数=1）
- 可实现资源计数（计数>1）
- 可跨进程使用

---

#### （5）自旋锁（Spinlock）

忙等锁，不让出 CPU。

```c
pthread_spin_lock(&spin);
pthread_spin_unlock(&spin);
```

**特点：**

- 临界区极短时性能极高
- 不适合单核 CPU
- 不会阻塞线程（忙等）

---

#### （6）原子操作（Atomic）

硬件级别保证操作不可分割。

```cpp
std::atomic<int> counter;
counter++;
```

**特点：**

- 单次读改写可以表达明确原子性与内存顺序
- 标准原子类型不保证在所有目标上都 lock-free，复杂或超出硬件宽度的操作可能由库或锁实现
- 性能要在目标平台测量，不能一概写成最高
- 适合简单变量操作（计数器、标志位）

---

### 同步机制对比（总结表）

| 同步方式 | 是否阻塞 | 性能 | 适用场景 |
|----------|----------|------|-----------|
| 互斥锁 | ✔ 阻塞 | 中 | 一般临界区 |
| 读写锁 | ✔ 阻塞 | 高（读多写少） | 多读少写 |
| 条件变量 | ✔ 阻塞 | 高 | 事件通知 |
| 信号量 | ✔ 阻塞 | 中 | 资源计数、跨进程 |
| 自旋锁 | ❌ 忙等 | 高（短临界区） | 多核、短操作 |
| 原子操作 | 视目标与类型而定 | 视争用与内存序而定 | 简单变量更新 |

---

### 总结

- 线程同步常用：**互斥锁、读写锁、条件变量、信号量、原子操作**
- 选择依据：
  - 临界区长度
  - 是否允许阻塞
  - 是否读多写少
  - 是否跨进程

一句话总结：

> **同步的本质是控制共享资源的访问顺序。**

## 进程之间的通信 IPC（Inter-Process Communication）

###  为什么需要进程间通信

- 进程之间 **地址空间隔离**
- 无法直接访问彼此内存
- 必须通过 **操作系统提供的 IPC 机制** 交换数据或同步

---

### 常见 IPC 通信方式

#### （1）管道（Pipe）

##### 匿名管道

```c
pipe(fd);
```

特点：

- 半双工
- 只能用于父子进程（有亲缘关系）

##### 命名管道（FIFO）

```c
mkfifo("fifo", 0666);
```

特点：

- 有文件名
- 可用于无亲缘关系进程

---

#### （2）信号（Signal）

用于事件通知。

```c
signal(SIGINT, handler);
```

特点：

- 异步
- 不能传递大量数据

---

#### （3）消息队列（Message Queue）

内核维护消息链表。

特点：

- 异步通信
- 消息有边界
- 支持结构化消息

---

#### （4）共享内存（Shared Memory）

多个进程映射同一块物理内存。

```c
shmget();
shmat();
```

特点：

- **最快的 IPC**
- 需要额外同步机制（信号量/互斥锁）

---

#### （5）信号量（Semaphore）

用于进程同步。

常与共享内存配合使用。

---

#### （6）Socket（套接字）

最通用的 IPC 方式。

```c
socket();
bind();
send();
recv();
```

特点：

- 可跨主机通信
- 网络通信的基础

---

### IPC 方式对比（总结表）

| IPC 方式 | 是否跨进程 | 是否跨主机 | 性能 | 特点 |
|----------|------------|------------|------|--------|
| 匿名管道 | ✔ | ✘ | 中 | 父子进程通信 |
| FIFO | ✔ | ✘ | 中 | 有文件名 |
| 信号 | ✔ | ✘ | 低 | 事件通知 |
| 消息队列 | ✔ | ✘ | 中 | 有消息边界 |
| 共享内存 | ✔ | ✘ | **最高** | 需同步机制 |
| 信号量 | ✔ | ✘ | 高 | 同步机制 |
| Socket | ✔ | ✔ | 中 | 最通用 |

---

### 总结

- 进程通信依赖 IPC 机制，包括：
  - 管道
  - 消息队列
  - 共享内存
  - 信号量
  - 信号
  - Socket
- 各有性能与使用场景
- **进程不共享内存，通信必须借助内核**

一句话总结：

> **线程靠共享内存 + 同步，进程靠 IPC + 内核。**

## 死锁与活锁

### 4.27.1 死锁（Deadlock）

#### 定义
死锁是指多个线程/进程因为 **相互等待对方持有的资源** 而永远无法继续执行。

#### 死锁的四个必要条件（必须全部满足）
1. **互斥条件**  
   资源一次只能被一个线程占用。

2. **请求与保持条件**  
   线程持有资源的同时又请求新的资源。

3. **不剥夺条件**  
   已分配的资源不能被强制剥夺，只能主动释放。

4. **循环等待条件**  
   存在一个线程等待环，每个线程都在等待下一个线程持有的资源。

> **四个条件缺一不可。破坏任意一个即可避免死锁。**

#### 死锁示例（经典 AB 互锁）

```c
lock(A);
lock(B);
```

```c
lock(B);
lock(A);
```

两个线程互相等待对方释放资源，导致死锁。

#### 死锁的解决方法
- **预防死锁**：破坏四个条件之一（如规定资源获取顺序）
- **避免死锁**：银行家算法等动态资源分配策略
- **检测与恢复**：周期性检测死锁并强制终止某个进程

---

### 4.27.2 活锁（Livelock）

#### 定义
活锁是指线程不断改变状态（例如不断重试），但 **没有实际进展**。

系统没有真正“卡住”，但也无法继续执行。

#### 死锁 vs 活锁

| 类型 | 状态 | 是否有进展 |
|------|------|------------|
| **死锁** | 线程全部阻塞 | ❌ 无进展 |
| **活锁** | 线程在忙碌运行 | ❌ 无进展 |

#### 活锁示例（双方不断让步）

```c
while (true) {
    if (try_lock() == false) {
        unlock();
        continue;  // 双方都在让步，永远无法获得锁
    }
}
```

#### 活锁的解决方法
- **限制重试次数**
- **随机等待（backoff）**
- **引入优先级或固定策略**

---

### 4.27.3 死锁与活锁对比（总结表）

| 项目 | 死锁 | 活锁 |
|------|------|------|
| 是否阻塞 | ✔ 阻塞 | ❌ 不阻塞（忙等） |
| CPU 使用率 | 低 | 高 |
| 是否有进展 | ❌ 无 | ❌ 无 |
| 触发原因 | 相互等待资源 | 过度让步、重复重试 |
| 解决方式 | 破坏四条件 | 随机等待、限制重试 |

---

### 4.27.4 总结

- **死锁：线程互相等待 → 永远不动**
- **活锁：线程一直动 → 永远没进展**

一句话记忆：

> **死锁是“卡住不动”，活锁是“忙着不干活”。**
