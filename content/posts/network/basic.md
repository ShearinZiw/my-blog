## OSI七层模型

### 物理层

1. 负责比特流的传输​
2. 定义电气特性、接口规范、信号电压、传输速率​
3. 不关心数据含义，只负责 0 和 1

### 数据链路层

1. 负责将比特流封装成帧​
2. 实现相邻节点之间的可靠传输​
3. 提供差错检测（CRC）

典型内容：​
- MAC 地址​
- 以太网协议​
- ARP 协议（地址解析）

### 网络层

1. 负责逻辑地址和路由选择​
2. 实现不同网络之间的数据转发​
3. 决定数据包从源到目的的路径

- IP 协议
- IP 地址
- 路由协议

### 传输层

1. 提供端到端通信​
2. 负责数据分段、重组​
3. 保证或不保证数据可靠性

### 会话层

1. 负责建立、管理和终止会话​
2. 控制通信过程中的会话状态​
3. 支持会话同步和恢复

### 表示层

1. 负责数据格式转换​
2. 处理数据编码、加密、解密、压缩​
3. 屏蔽不同系统的数据表示差异

- 字符编码（ASCII、UTF-8）​
- 数据压缩​
- SSL/TLS（概念上属于该层）

### 应用层

1. 直接面向用户和应用程序​
2. 提供网络服务接口​
3. 定义具体应用协议

---

## 应用层、传输层、网络层分别解决什么问题？

### 应用层（Application Layer）

**作用：**  
为用户和应用程序提供网络服务接口。

**解决的问题：**
- 定义应用数据格式（HTTP、FTP、MQTT）
- 提供应用间通信协议（文件传输、消息、远程控制）
- 数据语义处理（编码、压缩、序列化）

**典型协议：**HTTP、HTTPS、FTP、SMTP、DNS、MQTT

一句话：

> **应用层关心“数据内容是什么”。**

---

### 传输层（Transport Layer）

**作用：**  
实现端到端通信，确保数据从源主机传到目标主机的应用进程。

**解决的问题：**
- **端口管理**：区分不同应用进程
- **可靠传输（TCP）**：顺序、重传、校验、流控、拥塞控制
- **不可靠快速传输（UDP）**：低延迟、广播/组播
- **多路复用**：一台主机可同时处理多个连接

**典型协议：**TCP、UDP

一句话：

> **传输层关心“数据如何可靠送到正确的进程”。**

---

### 网络层（Network Layer）

**作用：**  
实现跨网络的数据转发与寻址。

**解决的问题：**
- **IP 地址**：逻辑寻址
- **路由选择**：决定数据走哪条路径
- **分片与重组**：适应不同网络的 MTU
- **差错检测、拥塞控制（部分）**

**典型协议：**IP、ICMP、ARP（辅助映射 IP→MAC）

一句话：

> **网络层关心“数据如何从一台主机送到另一台主机”。**

---

### 总结（面试可背诵）

- **应用层：**解决应用通信问题（数据内容）  
- **传输层：**解决端到端可靠性与端口管理  
- **网络层：**解决跨网络寻址与路由转发  

一句话：

> **应用层管内容，传输层管可靠性，网络层管路径。**

---

## 数据在网络中如何逐层封装和解封装？

### 数据封装（发送端）

从上到下逐层加头（有时加尾）：

1. **应用层**
   - 生成应用数据（HTTP 请求、文件等）
   - 加应用层协议头  
   → **Application Data**

2. **传输层**
   - 加 TCP/UDP 头（端口号、序列号、校验和）  
   → **TCP Segment / UDP Datagram**

3. **网络层**
   - 加 IP 头（源 IP、目的 IP、TTL）  
   → **IP Packet**

4. **数据链路层**
   - 加 MAC 头和帧尾（源 MAC、目的 MAC、CRC）  
   → **Frame（帧）**
   - 发送到物理介质（电信号/光信号）

---

### 数据解封装（接收端）

从下到上逐层去头：

1. **数据链路层**
   - 校验 MAC、CRC
   - 去掉帧头/帧尾 → 得到 IP 包

2. **网络层**
   - 解析 IP 头，确认目标 IP
   - 去掉 IP 头 → 得到 TCP/UDP 段

3. **传输层**
   - 解析端口号，找到目标进程
   - TCP 校验序列号、校验和
   - 去掉传输层头 → 得到应用数据

4. **应用层**
   - 应用程序解析协议内容
   - 恢复原始数据

---

### 总结（面试可背诵）

- **封装：**应用 → 传输 → 网络 → 链路（逐层加头）  
- **解封装：**链路 → 网络 → 传输 → 应用（逐层去头）  
- 每层只关心自己的头部，上层对下层透明

一句话：

> **发送端逐层加头，接收端逐层去头，最终恢复应用数据。**


## TCP/IP 是什么？

### 基本概念

**TCP/IP（Transmission Control Protocol / Internet Protocol）** 是一组网络通信协议的统称，用于指导网络中设备如何通信。

它是：

- **互联网的基础协议栈**
- **跨平台、跨设备的通用网络标准**
- 由多个协议组成，其中核心是 **TCP** 和 **IP**

一句话：

> **TCP/IP = 可靠传输（TCP） + 地址路由（IP）**

---

### TCP 与 IP 的职责

#### IP（Internet Protocol）
- 负责 **寻址与路由**
- 将数据包从源主机送到目标主机
- **无连接、不可靠**
- 不保证顺序、不保证到达
- 包含 IPv4 / IPv6

#### TCP（Transmission Control Protocol）
- 负责 **可靠的端到端传输**
- 面向连接（三次握手）
- 保证：
  - 顺序
  - 无丢失（重传机制）
  - 无重复
  - 流量控制
  - 拥塞控制

一句话：

> **IP 负责“送到哪”，TCP 负责“送得对”。**

---

### TCP/IP 四层模型

| 层级 | 作用 | 典型协议 |
|------|------|-----------|
| **应用层** | 为应用提供网络服务 | HTTP, FTP, DNS |
| **传输层** | 端到端通信 | TCP, UDP |
| **网络层** | 路由与寻址 | IP, ICMP |
| **网络接口层** | 物理传输 | Ethernet, WiFi |

---

### 工作流程（简述）

1. **应用层** 生成数据（如 HTTP 请求）
2. **TCP** 负责分段、可靠传输
3. **IP** 负责寻址、路由
4. **链路层** 负责实际发送（以太网帧）
5. 目标主机逐层解封装，最终交给应用程序

一句话：

> **应用 → TCP → IP → 链路 → 物理介质**

---

### 总结

- TCP/IP 是互联网通信的基础
- TCP 提供可靠性，IP 提供寻址与路由
- 采用分层结构，模块化、可扩展

## 子网掩码（Subnet Mask）

### 基本概念

子网掩码用于：

- **划分 IP 地址的网络部分与主机部分**
- 判断两台主机是否在同一子网
- 进行网络分段，提高管理效率

子网掩码由 **连续的 1（网络位）+ 连续的 0（主机位）** 组成。

---

### 原理

IP 地址 = **网络号 + 主机号**

示例：

```
IP:        192.168.1.10
子网掩码:  255.255.255.0 (/24)
```

二进制：

```
IP:    11000000.10101000.00000001.00001010
Mask:  11111111.11111111.11111111.00000000
```

计算：

- **网络号 = IP & Mask = 192.168.1.0**
- **主机号 = IP & (~Mask) = 0.0.0.10**

---

### 子网掩码的功能

#### 1. 区分网络与主机
- 网络号相同 → 同一子网
- 网络号不同 → 不同子网

#### 2. 划分子网
- 将大网络拆成多个小网络，提高管理灵活性

#### 3. 计算广播地址
- 广播地址 = 网络号 + 主机位全 1

---

### 常用子网掩码

| 掩码 | CIDR | 主机数 |
|------|------|---------|
| 255.255.255.0 | /24 | 254 |
| 255.255.0.0 | /16 | 65534 |
| 255.0.0.0 | /8 | 16777214 |

“/24” 表示前 24 位为网络位。

---

### 总结

- 子网掩码用于区分网络位与主机位
- 通过掩码可判断是否同一子网
- 是 IP 地址规划与网络管理的核心工具
